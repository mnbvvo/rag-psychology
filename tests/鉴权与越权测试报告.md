## 一、鉴权与越权的作用（为什么需要这套机制）

### 1.1 概念区分

| 术语 | 英文 | 回答的问题 | 类比 |
|---|---|---|---|
| **认证（鉴权）** | Authentication | 「你是谁？」——确认身份 | 出示身份证 |
| **授权** | Authorization | 「你能做什么？」——确认权限范围 | 门禁卡能开哪些门 |
| **越权** | Privilege Escalation | 攻击者拿到了不属于自己的权限 | 用别人的门禁卡开门 |

**认证 ≠ 授权**：登录成功只代表「你是你」，不代表「你能访问一切」。系统必须在每次访问资源时二次确认「这个资源属于你、且你的角色允许访问」。

### 1.2 越权攻击的两种典型形态

```
水平越权（Horizontal）          垂直越权（Vertical）
┌──────────────────┐          ┌──────────────────┐
│  用户 A  ──────►  用户 B     │  普通用户 ────►  管理员 |
│  (访问 B 的会话/  │          │  (访问 admin 接口) │
│   提示词/私密数据)│          └──────────────────┘
└──────────────────┘
A 用自己合法的身份，         普通用户用自己合法的身份，
去读取/修改 B 的数据         去执行管理员才能做的操作
```

- **水平越权**：同一角色内，用户 A 访问用户 B 的资源（如读 B 的对话记录、改 B 的提示词）。危害：隐私泄露。
- **垂直越权**：低权限角色访问高权限功能（如普通用户访问 `/api/admin/*`）。危害：越权管理操作。

### 1.3 为什么心理系统尤其重要

本项目存储的是**青少年心理健康对话记录与危机干预审计**，属于高敏感个人信息：

- 泄露 = 未成年人隐私外泄，可能造成二次伤害；
- 篡改 = 危机审计被伪造/删除，合规留痕失效；
- 因此「A 写入的数据 B 查不到」是本系统**硬性安全需求**，也是本次测试的核心断言。

### 1.4 本系统的三层防线（对应测试的每个断言）

```
请求 → [L1 认证层] → [L2 授权层] → [L3 所有权层] → 业务处理
       JWT 校验        RBAC 角色       归属校验
       失败 → 401      失败 → 403      失败 → 403
```

| 防线 | 机制 | 拦截的攻击 | 对应断言 |
|---|---|---|---|
| L1 认证 | Bearer JWT（无/无效/过期 → 401） | 未登录访问 | 无 token → 401 |
| L2 授权 | 角色校验 `require_admin`（普通 → 403） | 垂直越权 | 普通 token 访问 admin → 403 |
| L3 所有权 | 资源按 `user_id` 过滤 + 归属校验 | 水平越权 | A 访问 B 资源 → 403 |
| 身份铁律 | `user_id` 一律从 token 取，请求体携带的不信任 | 请求体篡改 user_id | 篡改 → 403 |
| 数据隔离 | 列表接口强制 `WHERE user_id = 当前用户` | 枚举/遍历他人数据 | A 写入 B 查不到 |

## 二、测试方法

### 2.1 测试目标（对应需求原文）

1. 注册 A/B 两账号各拿 token；
2. 遍历所有受保护接口，分别用：
   - 无 token → 断言 **401**
   - A 的 token 访问 B 的资源（水平越权）→ 断言 **403**
   - 普通 token 访问管理员接口（垂直越权）→ 断言 **403**
   - 请求体篡改 user_id → 断言 **403**
3. 断言 A 写入的数据 B 查不到。

### 2.2 受保护接口清单（全部要求登录）

| 接口 | 方法 | 认证 | 归属校验 |
|---|---|---|---|
| `/api/auth/me` | GET | ✅ | token 自身 |
| `/api/query` / `/api/query/stream` | POST | ✅ | session_id / prompt_id / user_id 篡改 |
| `/api/sessions` | GET / POST | ✅ | 列表只返回本人；创建归属本人 |
| `/api/sessions/{id}` | PATCH / DELETE | ✅ | 非本人 → 403 |
| `/api/sessions/{id}/messages` | GET | ✅ | 非本人 → 403 |
| `/api/system-prompt` | GET / PUT | ✅ | 提示词按用户隔离；操作他人 id → 403 |
| `/api/system-prompt/reset` | POST | ✅ | 只重置本人 |
| `/api/compare-history` | GET / POST / DELETE | ✅ | 非本人记录 → 403 |
| `/api/admin/users` | GET | ✅ + admin 角色 | 普通用户 → 403 |
| `/api/admin/crisis-audit` | GET | ✅ + admin 角色 | 普通用户 → 403 |

### 2.3 测试用例矩阵（42 项断言）

| 分组 | 用例 | 断言 |
|---|---|---|
| 注册 | 注册 A / B | 201 |
| 注册 | 重复注册 A | 409 |
| 注册 | 非法用户名 / 弱密码 | 400 |
| 登录 | 登录 A / B / admin | 200 + token |
| 登录 | 错误密码 | 401 |
| 无 token | 遍历 7 个受保护接口 | 401 |
| 水平越权 | B 读/改/删 A 的会话 | 403 |
| 水平越权 | B 删 A 的对比记录 | 403 |
| 水平越权 | B 更新/删除/激活 A 的提示词 | 403 |
| 水平越权 | B 用 A 的 session_id / prompt_id 调 `/api/query` | 403 |
| 垂直越权 | 普通用户访问 `/api/admin/*` | 403 |
| 垂直越权 | 管理员访问 `/api/admin/*` | 200 |

| 数据隔离 | A 读取自己的会话消息 | 200 |

### 4.2 过程说明（中途曾出现 39/42）

首次运行结果为 **39/42**，3 项失败集中在「管理员正例」（验证管理员能访问 admin 接口）：


| 项目 | 说明 |

## 五、结论

1. **鉴权与越权防护验证通过**：认证（401）、授权（403）、所有权（403）、身份铁律（篡改 user_id 无效）、数据隔离（A 写 B 查不到）五类断言 **42/42 全部通过**，未发现可利用的越权路径；
2. 中途 39/42 的 3 项失败系**测试脚本未传入正确管理员密码**所致，非系统缺陷；修正后（`--admin-password 123456789`）**42/42 全部通过**，且所有安全断言从未失败；
3. 测试脚本自动清理测试账号，未污染业务数据（当前用户：admin / legacy / mujin）。
