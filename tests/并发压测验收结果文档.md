## 1. 执行方法（对应方案 §3）

- **Mock**：自建 OpenAI 兼容服务器（`mock_openai_server.py`），支持固定延迟（--delay）、故障注入（`--fail-chat=500|429|hang|drop|timeout`、`--fail-embed=500|timeout|drop`、--fail-ratio）。embedding 返回确定性 1024 维向量。
- **驱动**：`tests/concurrency_pressure_test.py`（boundary/steady/spike 模式）+ 编排脚本（FIFO/取消/隔离/幂等等，见 §10 证据清单），均带严格断言（拒绝数精确匹配、峰值阈值、终态正确性）。
- **计费隔离**：Mock 阶段服务经环境变量指向 127.0.0.1:18080，未消耗真实额度；真实阶段直连 `.env` 端点。
- **登录限流干扰消除**：多档连跑注入 `LOGIN_IP_MAX_REQUESTS/REGISTER_IP_MAX_REQUESTS/RATE_LIMIT_TIMES=1000000`（env 化修复后可行）。

## 5. 取消/断线/异常释放 R-01~R-10（方案 §7）

| 项 | 注入方式 | 结果 |
|---|---|---|
| R-01 正常完成释放 | boundary 全档结束后 ≤8s 归零 | ✅ |
| R-02 LLM 500 | mock fail-chat=500 | ✅ HTTP 500 / 1.6s（SDK 有限重试）/ 槽位归零 |
| R-03 LLM 429 | mock fail-chat=429 | ✅ 2.1s 内失败（按 Retry-After 重试后释放，未无限占槽） |
| R-04 embedding 故障 | fail-embed=500（降级 200）与 =timeout（97.1s≈3×30s 后降级 200、零后台残留） | ✅ |
| R-05 SSE 运行中断连 | 客户端 2s 断开（首 token 前） | ✅ 0.5s 内 active 归零 |
| R-06 同步客户端断开 | 0.5s 断开连接 | ✅ 未提前释放（无超卖），底层完成后归零 |
| R-07 排队请求取消 | 21 SSE 取 1 排队者：他人 403、owner 200(10ms)、1s 内 queued→0、被取消者 error 非 done | ✅ |
| R-08 持久化失败 | 函数级 DB 故障（monkeypatch）：重试后 failures+2 / critical+1、不抛异常（回答契约保持） | ✅（函数级；E2E 停库留预发环境） |
| R-09 cancel/release 竞态 | 幂等抽查：重复取消 409、越权 403、不存在 409，无 500 | ✅（抽查级；确定性千次注入需设施） |
| R-10 SSE 排队中断连 | 两阶段编排（20 占槽 + 1 排队断连） | ✅（P0 泄漏修复后：1.5s 内 queued→0、不被提升、20/20 done） |

> **R-10 修复（P0，测试发现）**：排队断连 → event_stream 提前退出 → release 对 queued 条目无效 → 残留被提升为无消费者的 running → 槽位永久泄漏（实测 active=1 超 60s）。修复 = finally 补幂等 cancel 清理 queued 残留。
